# Build log

Each team member keeps their own copy of this file (for example `BUILD_LOG-paula.md`). It is graded, and it is the source of
your reflection memo in session 5. Write as you go; a log written afterwards is easy to spot.

One entry per working block. Five lines are enough.

## Template

**Date and session:**
**What I asked for** (paste the prompt, or its first lines):
**What the assistant did:**
**What I decided, and why:**
**What went wrong, and what I learned:**
**Checkpoint saved** (name):

---

## Example

**Date and session:** 12 November, session 1 lab
**What I asked for:** "Build a one-screen app where a rep pastes a customer's message, picks the customer from a list of eight invented names, and saves it to today's list."
**What the assistant did:** One page with a text box, a customer picker and a Save button. The list shows customer, time and the start of the message.
**What I decided, and why:** Kept the list newest first, because reps answer the latest request first. Refused the search box it offered: nobody asked for it.
**What went wrong, and what I learned:** On my phone the picker covered the Save button. I described exactly what I saw and it was fixed in one request. A bug is a conversation, not a reason to start again.
**Checkpoint saved:** "v0 works on a phone"
